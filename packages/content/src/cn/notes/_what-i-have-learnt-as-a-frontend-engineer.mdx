四年前，frontend engineering 看起来就是把设计变成精致的界面。Production 教会了不同的功课：架构、数据新鲜度、可靠性、交付，以及可衡量的用户结果，都是这份工作的一部分。

<br />

- 以下指标是 **项目成果**，不是通用基准。
- 重要的是技术决策与 **可观察结果** 之间的联系。

<br />

## 成果一览

- **Architecture：** page load 加快 80%、search latency 降低 90%，PageSpeed 高于 90。
- **Web performance：** LCP 低于 0.5 秒，CLS 低于 0.1。
- **Mobile reliability：** 上线后 crash-free sessions 超过 99.5%。
- **Delivery：** 用 SST 把 build 与 deployment 时间缩短超过 50%。

<br />

## 四堂课

1. **架构改动胜过局部优化。** 在调 React tree 之前，先衡量整条路径。
2. **Caching 是 freshness 政策。** Static content、编辑更新，与可变数据有不同的 lifecycles。
3. **Reliability 是面向用户的。** Dropped frames、memory 增长、loading failures 与 crashes，打断的是同一段旅程。
4. **Delivery system 是产品的一部分。** 共用基础与更安全的 releases，会在团队之间复利。

  <AccordionItem value="architecture">
    <AccordionTrigger>1. 修好真正的瓶颈</AccordionTrigger>
    <AccordionContent>

      - 遗留的 **WordPress** stack 是 page delivery 与 search 的瓶颈。
      - **Strapi / Sanity** 管理结构化内容与编辑工作流。
      - **Meilisearch / Algolia** 负责 indexing 与 retrieval。
      - **Next.js** 负责 rendering、caching 与用户体验。
      - Page load 下降 **80%**，search latency 下降 **90%**。代价是必须拥有 previews、webhooks、indexing 与 invalidation。
      - Browser optimization 仍然重要；最大的收益可能在 **上游**。参见 [Browser 中的 Critical Rendering Path](/notes/critical-rendering-path-in-the-browser)。

    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="caching">
    <AccordionTrigger>2. 让 cache 匹配数据</AccordionTrigger>
    <AccordionContent>

      - 一个 content platform 需要快速的公开页面、即时的编辑更新，以及交互式 workspaces。单一 cache strategy 无法同时服务这三者。
      - 预先 generate 核心页面与最新的 **100 篇文章**；按需 generate long-tail content。
      - 当 Strapi 发布时，按 tag invalidate 受影响的页面。
      - 在 server 上 prefetch 可变的 workspace 数据，然后 hydrate **TanStack Query**。在 query keys 中纳入 organization 与 URL filters，以避免 tenant 或 search 碰撞。
      - Content site 达到 **LCP 低于 0.5 秒**、**CLS 低于 0.1**，以及 PageSpeed 高于 **90**。
      - Hydration 改善了交付；**authorization** 仍然属于 API 之后。

    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="reliability">
    <AccordionTrigger>3. 拿掉用户看不见的工作</AccordionTrigger>
    <AccordionContent>

      - 用 **FlashList** 回收长列表；调整 rendering windows，而不是急于 mount 全部内容。
      - Freeze 非活跃屏幕，并延迟 mounts。
      - Cache 远程图片，并避免过大的 assets。
      - 只在 native-thread execution 有帮助时使用 **Reanimated**。
      - 发布后仍持续进行 device profiling 与 **Sentry** monitoring。
      - 应用维持超过 **99.5% crash-free sessions**——这是 reliability baseline，不是上线当天的主观感觉。

    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="delivery">
    <AccordionTrigger>4. 改善 frontend 如何交付</AccordionTrigger>
    <AccordionContent>

      - 横跨 **15+ React 与 React Native applications**，重复的摩擦变成了 delivery risk。
      - 用 **Radix**、**Tailwind CSS** 与可重用 hooks 建立共用 primitives；示例放在 **Storybook**、**Fumadocs** 与 MDX。
      - 以 **Cypress** 覆盖关键 journeys；用 **SST** 把基础设施与 deployment configuration 写成代码。
      - SST 将 build 与 deployment 时间缩短了 **超过 50%**。
      - 这 15+ 个 applications 是作品集背景，不是 design-system 影响力的证明；那需要 adoption、duplication、onboarding 与 regression metrics。
      - 相关：[Frontend Regression Tests](/notes/frontend-regression-test) 与 [用 SST 管理 AWS 基础设施与 DevOps](/notes/using-sst-for-aws-infra-and-devops)。

    </AccordionContent>
  </AccordionItem>
</Accordion>

## 「Senior」现在的意义

- 衡量 **用户旅程**，而不只是 component render time。
- 让 **架构对准瓶颈**，即使它落在 frontend repository 之外。
- 建模 **freshness 与 ownership**，而不是被动地加 caches。
- 用真实的 reliability signals **在发布后运营产品**。
- 通过共用基础、tests 与更安全的 delivery，改善 **下一位工程师** 的路径。
- Framework APIs 会变。这个循环背后的判断力，应该仍然有用。

<br />

```text
Establish a baseline → Understand constraints → Make the trade-off → Ship safely → Verify the outcome
```
