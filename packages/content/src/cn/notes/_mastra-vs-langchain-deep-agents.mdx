---
title: Mastra vs LangChain
description: 一份实用比较，对照 Mastra 与 LangChain Deep Agents 在 TypeScript workflows、durable sessions、RAG 与 production deployment 上的取舍
category: ai
---

**Mastra** 与 **LangChain Deep Agents** 都支持 agents、tools、memory 与 streaming。真正的差异，在于各自把边界划在哪里。

Mastra 是一套整合式 TypeScript framework，面向 AI applications。Agents、workflows、memory、RAG、evaluation、observability、local Studio、server，以及 deployment adapters，共用同一套 programming model。

Deep Agents 是建立在 **LangChain** 与 **LangGraph** 之上、带有明确意见的 autonomous-agent harness。它提供 files、context offloading、subagents、memory 与 middleware，然后依赖 LangChain 做 retrieval、LangGraph 做 explicit workflows 与 persistence，以及 LangSmith 做 operations。

- 当 agents 是更广泛应用里、deterministic workflows 的一部分时，选 **Mastra**。
- 当你做的是围绕 files、subagents 与 context management 的 autonomous research、coding 或 operations agents 时，选 **Deep Agents**。
- 在投入任何一边之前，先验证 **durability 与 deployment model**。

<br />

## 1. The Core Difference

Deep Agents 不是用来取代 LangChain。`deepagents` package 把 LangChain 与 LangGraph 组装成预建的 agent harness。

- Virtual filesystem、automatic context summarization、subagent delegation、file-based skills 与 memory，以及用于 retries、approvals 与 guardrails 的 middleware。
- Mastra 从更宽的 application boundary 起步。它的 `Agent` 只是众多 primitives 之一，与 tools、workflows、storage、vector stores、scorers、API routes 与 deployment configuration 并列。

| Area                    | Mastra                                    | Deep Agents                        |
| ----------------------- | ----------------------------------------- | ---------------------------------- |
| Primary abstraction     | AI application framework                  | Autonomous agent harness           |
| Deterministic workflows | First-class                               | Built with LangGraph               |
| Multi-agent model       | Agents and workflows exposed as tools     | Supervisor delegates to subagents  |
| RAG                     | Mastra packages and integrations          | LangChain retrieval ecosystem      |
| Persistence             | Mastra memory and durable execution       | LangGraph checkpointers and stores |
| File context            | Workspaces, skills, and file-based agents | Foundational virtual filesystem    |
| Managed runtime         | Mastra Platform                           | Managed Deep Agents or LangSmith   |

Mastra 在 package 层面更广。若把周边 LangChain ecosystem 算进去，Deep Agents 的覆盖面就会变得更广。

## 2. Building an Agent

两边都支持 TypeScript、Zod-validated tools，以及 model streaming。差异不在 type safety。

<br />

```ts title="src/mastra/agents/support-agent.ts"
import { Agent } from "@mastra/core/agent"
import { createTool } from "@mastra/core/tools"
import { z } from "zod"

const searchDocs = createTool({
  id: "search-docs",
  description: "Search product documentation",
  inputSchema: z.object({ query: z.string() }),
  execute: async ({ query }) => searchProductDocs(query),
})

export const supportAgent = new Agent({
  id: "support-agent",
  name: "Support Agent",
  instructions: "Answer from the documentation and cite the evidence.",
  model: process.env.AGENT_MODEL!,
  tools: { searchDocs },
})
```

<br />

```ts
import { createDeepAgent } from "deepagents"
import { tool } from "langchain"
import { z } from "zod"

const searchDocs = tool(({ query }) => searchProductDocs(query), {
  name: "search_docs",
  description: "Search product documentation",
  schema: z.object({ query: z.string() }),
})

export const supportAgent = createDeepAgent({
  model: process.env.AGENT_MODEL!,
  systemPrompt: "Answer from the documentation and cite the evidence.",
  tools: [searchDocs],
})
```

<br />

- Mastra 的 registries 与 shared resource model 感觉像 application framework；Deep Agents 感觉像在配置一套 graph-backed runtime。
- Mastra 的 local server 与 Studio 暴露 agents、workflows、traces、datasets 与 scorers。
- 一套完整的 Deep Agents application 通常横跨 `Deep Agents → LangChain → LangGraph → LangSmith`（harness、tools、state、operations）。
- Mastra 在它打算走的路上减少概念跳跃。Deep Agents 在需要更多控制时，提供直接逃进 LangGraph 的 hatches。

<br />

## 3. Deterministic Workflows

Agent 让 model 选择下一步发生什么。**Workflow** 则把重要 transitions 写进代码里。

- 当序列是一条 business rule 时用 workflow：validate input、collect data、request approval、publish，并记录结果。
- Mastra workflows 是 first-class、typed primitives。Steps 声明 input 与 output schemas，可以顺序、并行、经 branches，或在 loops 里组合。
- Steps 可以为 human approval 而 suspend，再用 typed payload resume。Model 在 step **里面** 仍保持灵活，但不控制整个过程。

<br />

```ts
const articleWorkflow = createWorkflow({
  id: "article-workflow",
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ article: z.string() }),
})
  .then(research)
  .then(write)
  .then(approve)
  .commit()
```

<br />

- Deep Agents 的 subagent delegation 是 model-directed，不是 deterministic workflow。要 explicit state 与 transitions，就跟 LangGraph 组合：nodes、edges、checkpoints、interrupts、streaming、subgraphs。
- 对 workflow-heavy products，Mastra 通常是更短的路。对已经在用 LangGraph 的团队，Deep Agent 可以是自定义 state machine 里一个有能力的 node。

**Failure：** 把 subagent delegation 当成 business-rule DAG 的替代。LangGraph 的成本是自己管理 graph state、reducers、nodes 与 transitions。

<br />

## 4. Durability and Memory

「Memory」常常把好几项分开的需求藏在一起：

1. **Message history** 让 conversation 保持连贯。
2. **Working memory** 存放 preferences、goals 或 task state。
3. **Long-term memory** 跨 conversations 共享知识。
4. **Durable execution** 恢复被打断的工作。
5. **Resumable streaming** 让 client 重新接到正在跑的 task。

Persisted messages 并不会让任意代码变成 durable。

<br />

```ts
const memory = new Memory({
  storage: new PostgresStore({
    id: "support-memory",
    connectionString: process.env.DATABASE_URL!,
  }),
  options: {
    lastMessages: 20,
    workingMemory: { enabled: true },
  },
})

await agent.stream("Continue the migration plan", {
  memory: {
    thread: "conversation-42",
    resource: "user-123",
  },
})
```

<br />

- Mastra 的 `Memory` 把一次 conversation **thread** 关联到一个 user 或 tenant **resource**。它可以组合 recent messages、semantic recall、structured working memory，以及 observational memory。
- Durable-agent APIs 让 clients 用 run ID 重新接到长 streams。必须在 process crash 后活下来的工作，属于 durable 或 workflow-backed execution。
- LangGraph **checkpointer** 持久化 thread-scoped graph state、interrupts 与 resume points。LangGraph **store** 保存跨 threads 共享的数据。
- Deep Agents 把 long-term memory 表示成 files。`StateBackend` 把 scratch files 留在 thread state；`StoreBackend` 可以把 `/memories/` 与 `/skills/` 这类 paths 跨 threads 持久化。

**Failure：** 让 model 自己挑 identifiers 与 namespaces。它们必须来自 authenticated context。Durable memory 仍然需要 retention、correction 与 deletion policies。

<br />

## 5. RAG

一套 production RAG system 有分开的 ingestion 与 query paths：

```text
ingestion → load → chunk → embed → index
query     → retrieve → filter/rerank → answer with citations
```

- Ingestion 不该在每次 agent request 时跑。一次成功的 vector lookup 并不能证明答案是 grounded。
- Mastra 提供 document chunking、经 AI SDK model interface 的 embedding support、vector-store integrations，以及可以直接挂到 agent 上的 vector query tool。
- Dynamic vector-store resolution 特别适合从 authenticated request context 选出某个 tenant 的 index。
- Deep Agents 使用 LangChain loaders、text splitters、embeddings、retrievers 与 vector stores。Ecosystem 广度对 specialized document formats 或 retrieval strategies 很重要。
- Deep Agents 可以把 retrieved content 写进 backend 并返回 file paths，让 agent 只检查相关 sections，而不是把每个 token 都放进主 conversation。

无论走哪条路，都评估 retrieval recall 与 precision、answer groundedness、citation correctness，以及 end-to-end answer quality。

<br />

## 6. Files、Subagents 与 Sandboxes

Deep Agents 把 files 与 delegation 放在中心。Supervisor 可以把工作送给带 isolated context 的 subagents，让每个 specialist 做很多次 tool calls，再返回一份紧凑的结果。

- `StateBackend` 存储 thread-scoped virtual files。`FilesystemBackend` 暴露 host directory。`LocalShellBackend` 加上 host shell access。Provider-backed sandboxes 在远端隔离 files 与 processes。
- Mastra 可以把 agents 与 workflows 暴露给 routing agent，并附上包含 filesystem 与可选 sandbox 的 `Workspace`。这适合 file access 只是众多能力之一的 applications。
- Workspace path 不是 security boundary。无论哪个 framework，local shell execution 只适合 trusted development。

Production execution 需要一份全新或正确 namespaced 的 sandbox、CPU / memory / disk / time limits、受控的 network egress、明确的 file-transfer rules，以及范围很窄的 credentials。

**Failure：** 把 isolation 当成完整防御。它保护 host；它本身并不能阻止 prompt injection、secret exfiltration、runaway cost，或 cross-user leakage。

## 7. Observability、Evaluation 与 Safety

运营一个 agent 需要最终答案背后的路径：model calls、tools、retrieval、subagents、workflow transitions、retries、latency、token usage、cost 与 errors。

- Mastra 为自己的 primitives 做 instrumentation，并把 traces export 到 Studio、Mastra Platform，或 OpenTelemetry backends。它也在同一套 framework model 里包含 scorers、datasets 与 experiments。
- Deep Agents 继承 LangChain 与 LangGraph tracing。LangSmith 加上 dashboards、alerts、datasets、offline 与 online evaluators、annotation queues，以及 deployment monitoring。
- Mastra 的 observability 感觉像 framework primitive。LangSmith 是更广的 operations product。两边都可以参与既有的 OpenTelemetry pipeline。

在五个层级测试：

1. 不带 model calls 的 tool contracts
2. 带受控 responses 的 workflows 或 graphs
3. 针对 quality 与 groundedness 的 dataset evaluations
4. 针对 performance 与 failure paths 的 traces
5. 针对 streaming、persistence、authentication 与 limits 的 deployed behavior

两边都可以通过 suspended workflow steps、tool approval，或 LangGraph interrupts 做 human approval。Approval 不能取代 runtime isolation。Agent traces 可能包含 user messages、retrieved documents、tool arguments 与 generated code——套用与应用数据相同的 access controls、redaction、retention 与 deletion rules。

## 8. Deployment

第一个 agent demo 很容易。Production 需要 durable state、background execution、authentication、secrets、observability，以及能在真实基础设施上活下来的 streaming。

- Mastra 最整合的路径是 Mastra Platform（`mastra deploy`）。它也可以 build 一个 Node server，或瞄准 Cloudflare 这类 platforms。Portability 仍取决于 state：local SQLite files、vectors、memory 与 workflow data 必须换成与 runtime 兼容的 stores。
- Deep Agents 有三条主要路径：**Managed Deep Agents**（先验证可用性）、**LangSmith Deployment**（persistent state、background execution、authentication hooks、webhooks、cron、tracing、Agent Protocol APIs），以及用 Agent Streaming Protocol 在 Next.js 或 Cloudflare 上的 **application-hosted** deployment。

Application hosting 把更多责任转给团队：durable checkpointer 与 store、authenticate 并 authorize 每一个 thread、隔离 tenant namespaces、处理 host timeouts 与 background work，以及把 code execution sandbox 离开 web server。

| Requirement                 | Mastra                   | Deep Agents                                       |
| --------------------------- | ------------------------ | ------------------------------------------------- |
| Simplest hosted path        | Mastra Platform          | Managed Deep Agents                               |
| Established managed runtime | Mastra Platform          | LangSmith Deployment                              |
| Custom hosting              | Built server or adapter  | Agent Protocol routes or Agent Server             |
| Self-hosted durability      | Mastra storage providers | LangGraph checkpointer, store, and infrastructure |
| Enterprise topology         | Platform-dependent       | Cloud, hybrid, or self-hosted LangSmith           |

对 greenfield TypeScript 团队来说，Mastra 的整合路径更干净。若团队已投入 LangChain，或需要 hybrid infrastructure，LangSmith 提供更多 runtime topologies。

## How to Choose

<Accordion type="multiple">
  <AccordionItem value="mastra">
    <AccordionTrigger>Choose Mastra when</AccordionTrigger>
    <AccordionContent>

      - Agents 是 deterministic business workflows 的一部分
      - 团队想要一套 TypeScript model 同时涵盖 tools、memory、RAG、evaluation 与 deployment
      - 通过 Studio 做 local inspection 很重要
      - 尽快走到 hosted application 很关键

    </AccordionContent>
  </AccordionItem>
  <AccordionItem value="deep-agents">
    <AccordionTrigger>Choose Deep Agents when</AccordionTrigger>
    <AccordionContent>

      - 主要任务是 open-ended research、coding、analysis 或 operations
      - Subagent delegation 与 context isolation 是核心
      - Agent 需要 files、skills、memory files 或 sandboxed execution
      - 团队已经使用 LangChain、LangGraph 或 LangSmith
      - Graph state、middleware、persistence 或 runtime topology 需要深度定制

    </AccordionContent>
  </AccordionItem>
</Accordion>

<br />

| Need                            | Default                                         |
| ------------------------------- | ----------------------------------------------- |
| Deterministic workflows         | Mastra, unless the team already knows LangGraph |
| Conventional application memory | Mastra                                          |
| Filesystem-native memory        | Deep Agents                                     |
| Straightforward RAG             | Mastra                                          |
| Specialized retrieval           | Deep Agents with LangChain                      |
| Coding or research agent        | Deep Agents                                     |
| Managed operations              | Deep Agents with LangSmith                      |
| Existing OpenTelemetry pipeline | Either                                          |

没有万能赢家。Mastra 优化的是 **AI application**。Deep Agents 优化的是 **autonomous agent harness**，并把它接到更广的 LangChain stack。

在选定之前，先 prototype 最难的 production requirement：approval workflows 的 suspend 与 resume、重新接到 long-running research、在真实 documents 上测量 RAG，以及为 code execution 验证 sandbox 与 credential boundaries。

目前的细节见官方 [Mastra agents](https://mastra.ai/docs/agents/overview)、[workflows](https://mastra.ai/docs/workflows/overview)、[memory](https://mastra.ai/docs/memory/overview)、[RAG](https://mastra.ai/docs/rag/overview)、[workspaces](https://mastra.ai/docs/workspace/overview)、[observability](https://mastra.ai/docs/observability/tracing/overview)，以及 [deployment](https://mastra.ai/docs/mastra-platform/deploy) 文档。LangChain 方面见 [Deep Agents](https://docs.langchain.com/oss/javascript/deepagents/overview)、[memory](https://docs.langchain.com/oss/javascript/deepagents/memory)、[RAG](https://docs.langchain.com/oss/javascript/deepagents/rag)、[sandboxes](https://docs.langchain.com/oss/javascript/deepagents/sandboxes)、[LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence)、[LangSmith observability](https://docs.langchain.com/langsmith/observability)，以及 [production deployment](https://docs.langchain.com/oss/javascript/deepagents/going-to-production)。
